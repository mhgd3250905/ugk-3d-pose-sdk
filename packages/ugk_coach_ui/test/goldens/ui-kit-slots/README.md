# Defaults before optional rendering slots

All 16 PNGs were generated by `ui_kit_slots_default_golden_test.dart` against
**immutable SDK commit `caa6817c51b3cb09c46909288d83aa88bdc2dbd4`**, whose components
have no icon or cutout builder parameters. They were not approved by rendering
the new implementations and accepting their output.

`baseline-manifest.json` records the SHA-256 of every baseline library source,
the identical harness, the SDK Material Icons font, and every resulting PNG.
The source bytes were extracted
using `git ls-tree` plus `git show <commit>:<path>` into a separate ignored
package under `build/ui-kit-slots/baseline`. Its own locked dependencies were
resolved offline; no production source was swapped or reverted.

Generation in that baseline package:

```powershell
flutter pub get --offline --enforce-lockfile
flutter test --no-pub --update-goldens --reporter expanded test/ui_kit_slots_default_golden_test.dart
```

Copy only the generated PNGs into this directory. The current package runs the
same harness **without `--update-goldens`**, using Flutter's standard
`matchesGoldenFile` / `LocalFileComparator` with exact pixel equality:

```powershell
flutter test --no-pub --reporter expanded test/ui_kit_slots_default_golden_test.dart
```

The generation environment was Windows, Flutter `3.47.8`
(`737ba8f885dc774b53b442759999a312c9461e4e`), engine
`cf636b1dfb818dd6a3ff16e390e93b1a036969c8`, Dart `3.13.7`.
The harness fixes the test surface at 400 × 240 physical pixels with DPR 1,
uses the standard Flutter test font environment for text, and explicitly loads
the installed SDK's `MaterialIcons-Regular.otf` with `FontLoader`. It resolves
`package:flutter` from `.dart_tool/package_config.json`, then reads the SDK
cache font; no machine-specific path, copied font or new dependency is used.
Default bookmark/close and existing star/cancel arguments therefore draw their
actual, distinct glyphs rather than the same test-font placeholders. Both
light/dark `focus-visible` PNGs have different hashes from `focus-old-icon-data`.
Cutout fixtures are drawn deterministically in memory; there are no network
images or host font assets.
These regression images establish unchanged SDK rendering in that environment,
not host-app or device visual acceptance.

Each light/dark variant covers:

- Plan focus: halfway through entry (90 ms), fully visible, existing custom
  `IconData` arguments, and halfway through exit (60 ms).
- Task bubble: breathing core (450 ms), first provider-backed cutout reveal
  (305 ms), two-image crossfade (1025 ms), and completion check (260 ms).

Every constructor omits the new optional renderer slots. Existing
`cutoutFor` and `IconData` paths therefore remain independently guarded.
