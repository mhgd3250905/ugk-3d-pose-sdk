## 办公室「做成训练组」必失败（根修）

根因：QA 选动作只看 App ai-tags（`QaFinder.passes`：tags.scenes / requiredEquipment / floorRequired / space / jointStress），
refit、交付与恢复看 core（`NodeGates.actionProblem` / `PlanValidator`：目录 drill.scenes 对 profile `acceptDrillScenes`、
`forbidFloor`+position、器械声明、drill.cautions 对 avoid）。SF 的 `h-close-stance-forward-fold-native` 标签 scenes 含 office，
目录 scenes 只有 home/gym，于是 QA 圈进候选/热身收操/补位，core 判「场景不符合」：配时 refit 抛 `incompatible_action`，
时长恰好合格时绕过 refit 交付，恢复时又被 `admitTraining` 拒（`action_scope_violation`）。同理还有 avoid 对目录 cautions
（如 `h-incline-pushup` 肩）的不一致；热身/收操查询漏传 smallSpace / maxDifficulty。

改法：新增 `QaAdmission`（`lib/src/qa_v2/qa_admission.dart`）作唯一准入：同一场景映射（hotel/outdoor→home）、同一
器械声明（动作自身 requiredEquipment，与 `equipmentFor` 一致）、同一 avoid 规范化，调用 core `actionProblem`。
`QaFinder.passes` 先过它再做标签收窄；`fitForExecution` 用它构造 core 参数，且时长已合格也先过准入；热身/收操沿用
`base.scopeOnly`。未改标签/目录数据、未放宽门禁、无重试或跳过。`QaFinder` 现需 `profile:`（破坏性签名变更，App 未直接使用）。
`chat.turn.error` 观测事件改为 Map：`errorType`、`message`（≤300 字）、`error`（原对象）。
